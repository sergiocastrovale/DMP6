# Subsonic API

`/rest/*` (`web/server/routes/rest/[...path].ts`) implements the Subsonic/OpenSubsonic API
(https://opensubsonic.netlify.app) so third-party clients - Symfonium, Amperfy, play:Sub,
Substreamer, Feishin - can browse/stream/star/scrobble against DMP, with offline downloads,
Android Auto and CarPlay support coming from the client app, not DMP itself (DMP is a website; the
native client is what shows up in the car).

## Auth: apiKey only

Every other endpoint gate in the app checks a `dmp_session` cookie (`server/middleware/auth.ts`).
A native client can't do that interactive login, and DMP's passwords are bcrypt-hashed
(`server/utils/password.ts`), which rules out Subsonic's classic `u`/`p`/`t`
(`t = md5(password + salt)`) scheme - the server would need the plaintext password to check it.

So `/rest/*` accepts only the OpenSubsonic `apiKey` extension. A user generates a key at
**Settings → Subsonic** (`pages/settings/subsonic.vue`, `components/settings/SubsonicKeys.vue`) -
available to every role, not just admins, same as Themes. The plaintext key is shown exactly once,
right after creation (`POST /api/me/api-keys`); only its sha256 hash (`UserApiKey.keyHash`) is ever
stored (`server/utils/apiKeys.ts`). `u`/`p`/`t` requests are refused with error 42
(`PASSWORD_AUTH_NOT_SUPPORTED`), not silently ignored - a client without `apiKeyAuthentication`
support (check `getOpenSubsonicExtensions`) simply won't work here.

`server/middleware/auth.ts` exempts `/rest/` from the cookie check; the dispatcher
(`server/routes/rest/[...path].ts`) authenticates the request itself
(`server/utils/subsonic/auth.ts`) and sets `event.context.user`, so every handler downstream still
goes through the normal `requirePermission`/`currentUserId` (gated on `play.view` - the same
permission the web player uses). Failed keys are throttled through the same in-memory
`loginThrottle` as `/api/auth/login`.

## Envelope and format

Every response is `HTTP 200` with a `<subsonic-response>` (or `{"subsonic-response": ...}` for
`f=json`) envelope; failures live in `status="failed"` + an `<error code message>` inside the body,
never the HTTP status line (`server/utils/subsonic/response.ts`, error codes in
`server/utils/subsonic/errors.ts`). XML is generated by converting the same JSON-shaped payload
object every handler returns (`server/utils/subsonic/xml.ts`): a scalar field becomes an attribute,
a nested object a child element, a nested array repeated same-tagged elements - with one documented
exception (`genre`'s `value` renders as text content, not an attribute).

`formPost` (an OpenSubsonic extension, advertised via `getOpenSubsonicExtensions`) is supported: a
client may POST credentials as a urlencoded body instead of the query string, so an apiKey never
lands in a proxy/access log.

## Data model mapping

- **Artist** → only artists that own a release or were added via `./add`
  (`server/utils/subsonic/scope.ts`'s `subsonicArtistWhere`, same rule as `/browse`). A connected
  duplicate (`primaryArtistId` set) never appears on its own.
- **Album** (`getAlbum`/ID3 browsing) → `LocalRelease`, only ones with at least one local track
  (`subsonicAlbumWhere`) - a `MISSING` catalogue-gap placeholder has no file to stream.
- **Song** → `LocalReleaseTrack`.
- **Cover art** → `getCoverArt`'s `id` needs a prefix to say which table to resolve against
  (`ar-`/`al-`/`pl-`, `server/utils/subsonic/ids.ts`) since it's the one endpoint shared across
  entity types; every other endpoint's `id` is unambiguous from context and stays a bare cuid.
  Resolves through the same `verifyImage`/local-file-or-S3-redirect logic as `/img/*`
  (`server/utils/serveImage.ts`, shared by both).
- **Stream/download** → `server/utils/serveTrack.ts`'s `serveTrackFile`, extracted from
  `/api/audio/[id]` so both share the exact same range/ETag/NAS-proxy-fallback logic.
- **Star/unstar** → `FavoriteTrack`/`FavoriteRelease` (`server/utils/favorites.ts`). `artistId` is
  silently ignored - DMP has no per-user `FavoriteArtist`, only release/track favorites.
- **Scrobble** → `submission=true` synthesizes an already-finished, `counted` `PlayEvent`
  (`source: SUBSONIC`, `server/utils/playEvents.ts`'s `recordExternalPlay`) and folds it into
  `LocalReleaseTrackPlay` the same way a normal listen does. `submission=false` (now-playing) is a
  no-op - DMP has no now-playing broadcast surface for external players to feed.
- **Playlists** → `Playlist`/`PlaylistTrack`, scoped through the same
  `visiblePlaylistsWhere`/ownership rules as the web app (`libraryOwnership.ts`): a shared
  GENRE/REGION playlist is visible but never editable from `/rest/*` either.

## Endpoints (v1)

| Group | Endpoints |
|---|---|
| System | `ping`, `getLicense`, `getMusicFolders`, `getOpenSubsonicExtensions`, `getUser` |
| Browse (ID3) | `getArtists`, `getArtist`, `getAlbum`, `getSong`, `getGenres` |
| Lists | `getAlbumList2` (newest/alphabeticalByName/alphabeticalByArtist/byYear/byGenre/starred/frequent/recent/random), `getRandomSongs`, `getStarred2` |
| Search | `search3` (empty query = full paged listing ordered by id, for a client's initial library sync) |
| Media | `stream`, `download`, `getCoverArt` |
| Annotation | `star`, `unstar`, `scrobble` |
| Playlists | `getPlaylists`, `getPlaylist`, `createPlaylist` (new playlist only), `deletePlaylist` |

Registered in one table in `server/routes/rest/[...path].ts` (`JSON_ENDPOINTS` for handlers that
return a body to envelope, `RAW_ENDPOINTS` for the three media handlers that write their own
response). Each group's implementation lives in `server/utils/subsonic/endpoints/<group>.ts`.

**Not yet implemented** (follow-ups, not required by the target clients' core flows):
folder-style browsing (`getIndexes`/`getMusicDirectory` - every target client uses ID3 browsing),
`getArtistInfo2`/`getAlbumInfo2`, `getSongsByGenre`, `updatePlaylist` and `createPlaylist`'s
update-existing form, `setRating` (no-op if called), transcoding (`maxBitRate`/`format` params are
accepted but ignored - the original file is always served), video/podcast/jukebox/share (DMP has
none of these).

## Testing

- `test/server/utils/subsonic/*.test.ts` - pure logic: XML/JSON envelope, param parsing, error-code
  mapping, A-Z index grouping, cover-art id prefixing, shuffle/clamp, the row→Subsonic-shape mappers.
- `test/integration/subsonic/*.test.ts` - against real Postgres: apiKey lifecycle (create/resolve/
  revoke/throttle), star/unstar/scrobble, browse ownership scoping, playlist visibility/ownership.
- `e2e/settings-subsonic.spec.ts` - the key-reveal-once UI flow.
- `e2e/rest-api-smoke.spec.ts` - one real HTTP round trip through the dispatcher (JSON + XML,
  bad/legacy auth, unknown endpoint) - the one layer the function-level integration tests don't
  reach.
