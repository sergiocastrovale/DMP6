# Audit 2026-09-26: web app, infra and CI (everything except `scripts/`)

Scope: `web/` (server, stores, composables, components, pages, helpers, prisma schema/migrations), `mobile/`,
`Dockerfile`, `docker-compose.yml`, `.github/workflows/`, repo root. `scripts/` (Rust) was out of scope and
not reviewed.

Scale: **1.9M `LocalReleaseTrack` rows, 151k `LocalRelease`, 350k `MusicBrainzRelease`, 46k `Artist`,
database 12 GB on disk** (`LocalReleaseTrack` alone is 9.9 GB, of which the heap and TOAST are 8.7 GB,
mostly the `metadata` JSON at ~3.3 KB per row). Findings are judged at that size. A query that runs fine
on a dev fixture but seq-scans 2M rows, sorts every match, or ships every row to Node counts as a bug
here.

Method: static read of every server route and util, the Prisma schema and all 26 migrations, the stores,
the composables and the largest components/pages, plus greps across the whole tree (auth gates,
`readBody`, `any`, silent `catch`, polling, dead exports). A second pass (same day) probed the **live
database read-only** over `ssh nas` in a session forced to `default_transaction_read_only=on`: sizes,
index usage, extensions, data shape, and plain or read-only `EXPLAIN` of the hottest queries. The live
numbers are in §0, and every finding below has been corrected against them. **Part II** (at the end) is
the execution plan.

## 1. Security

### SEC-01 P0: terminal control endpoints only check "is logged in"
- **Where:** `server/api/terminal/unlock.post.ts`, `stop.post.ts`, `reconnect.post.ts`, `sessions.get.ts` (all
  gate on `event.context.user` only).
- **Problem:** `unlock` clears `Statistics.scanLock*` and kills **every** reconnectable tmux session. `stop`
  SIGTERMs the lock-holding PID. A VIEWER can abort an ADMIN's `--overwrite-with-images` rescan, `./nuke`
  or `./delete --files` mid-flight and drop the lock while a foreign process may still hold it. That is
  exactly what `scan/unlock.post.ts` guards against with `requireRole('ADMIN')`. `reconnect` lets any user
  stream any session's log.
- **Fix:** `unlock` → ADMIN, and merge it with `scan/unlock.post.ts` (the two duplicate each other, see
  CONS-06). `stop` → `sync.run`, plus ADMIN when the session is running a command from `COMMAND_PERM`
  = ADMIN (record the command beside the log). `reconnect`/`sessions` → `sync.view`. Also gate
  `plugins/terminalReconnect.client.ts` on `hasPerm('sync.view')` so VIEWER tabs stop polling. Add
  integration tests asserting 403 for VIEWER on all four.

### SEC-02 P1: no HTTP security headers on a publicly tunnelled app
- **Where:** nothing in `nuxt.config.ts` routeRules or `server/middleware`.
- **Problem:** the app is on the internet via Cloudflare Tunnel and sends no CSP, `frame-ancestors`,
  `X-Content-Type-Options`, `Referrer-Policy` or HSTS. That leaves it open to clickjacking of admin
  actions (terminal run, user delete) and MIME sniffing of `/img/*`.
- **Fix:** a `server/middleware/securityHeaders.ts` (or `routeRules['/**'].headers`) with
  `Content-Security-Policy` (self + Google Fonts until SEC-08, `img-src` self + storagePublicUrl,
  `media-src` self), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: same-origin`, HSTS when behind
  TLS.

### SEC-03 P1: throttle keys trust client-supplied `X-Forwarded-For`
- **Where:** `server/utils/subsonic/auth.ts:9` reads the raw `x-forwarded-for` header.
  `server/api/auth/login.post.ts` uses `getRequestIP(event, { xForwardedFor: true })`.
- **Problem:** rotating the header gives each attempt a fresh throttle key, which bypasses the brute-force
  lockout on both login and Subsonic apiKey auth. `loginThrottle.ts`'s `attempts` Map is also never
  pruned, so a username/IP spray grows it without bound.
- **Fix:** one `clientIp(event)` helper. It prefers `cf-connecting-ip` when a `TRUSTED_PROXY=cloudflare`
  env is set, otherwise uses the socket address. Add a periodic sweep of expired throttle entries (or an
  LRU cap).

### SEC-04 P1: `issues.view` authorizes writes and the file-writing `./fix`
- **Where:** `server/api/issues/[type]/[id].patch.ts`, `queue.post.ts`, `queue-revert.post.ts`,
  `history-undo.post.ts`, `history.delete.ts` (deletes the audit trail);
  `server/utils/terminalCommand.ts` `COMMAND_PERM['./fix'] = 'issues.view'`.
- **Problem:** granting "view issues" in the permission editor silently grants rewriting audio tags and
  deleting fix history.
- **Fix:** add `issues.fix` (writes, `./fix`, undo) and `issues.admin` (history delete). Update
  `shared/permissionsMatrix.ts` plus a seed/backfill migration.

### SEC-05 P2: RBAC split between the editable matrix and hard-coded roles
- **Where:** 18 routes use `requireRole('ADMIN')` or `requireRoleAtLeast` (users/*, permissions/*,
  playlist-generators/*, scrobble connect/callback, scan/unlock, labs/mosaic/*). `artists/monitor-selected`
  uses `variables.edit` while the single-artist toggle `artists/[slug].patch` uses `downloads.crud`.
- **Problem:** Settings → Permissions looks authoritative, but half the surface ignores it. The two
  monitoring toggles disagree.
- **Fix:** introduce `users.manage`, `permissions.manage`, `playlists.generate`, `labs.mosaic` and
  `terminal.control`, move every route onto `requirePermission`, and keep `requireRole` for "last admin"
  invariants only. Align `monitor-selected` to `downloads.crud`.

### SEC-06 P2: settings secrets stored in plaintext
- **Where:** `Settings.slskdApiKey`, `awsSecretAccessKey`, `lastfmSecret`, `lastfmSessionKey`,
  `geniusSecret`, `geniusAccessToken`. `fanartApiKey` is missing from `SECRET_SETTINGS_FIELDS`, so it is
  returned unmasked.
- **Problem:** every `./backup` dump and any DB read replica carries live credentials.
- **Fix:** AES-GCM encrypt at rest with a dedicated `SETTINGS_ENCRYPTION_KEY` env (not `SESSION_SECRET`,
  so rotating one doesn't brick the other). Decrypt inside the settings resolver (CONS-07). Add
  `fanartApiKey` to the masked list.

### SEC-07 P2: Subsonic `download` builds `Content-Disposition` from the raw filename
- **Where:** `server/utils/serveTrack.ts:56`.
- **Problem:** Node rejects header values containing characters above `\xFF` (`ERR_INVALID_CHAR`). Any
  CJK, Cyrillic or Greek filename 500s on `/rest/download`, and a `"` in a filename breaks the header.
- **Fix:** `attachment; filename="<ascii fallback>"; filename*=UTF-8''<encodeURIComponent(name)>`.

### SEC-09 P1 (new, live probe): the app, the scripts and migrations all connect as a Postgres SUPERUSER
- **Where:** the `dmp` role (`rolsuper = t`) in `DATABASE_URL` on the NAS and locally.
- **Problem:** any SQL injection, or any `$queryRawUnsafe` slip, gets full cluster control: other
  databases, `COPY … TO PROGRAM`, reading server files. A superuser also bypasses every future
  `statement_timeout`/role limit and can't be given one without affecting the Rust scripts, which share
  the role.
- **Fix (needs the user, D3):** create `dmp_web` (LOGIN, no superuser, `CONNECT` on `dmp`, DML on the
  public schema, `statement_timeout = '15s'`), point the web container's `DATABASE_URL` at it, and keep
  `dmp` for migrations and scripts. It touches NAS Postgres roles and the compose env, so it is not a
  Sonnet task.

### SEC-08 P3: smaller items
- `scrobble/callback.get.ts` mutates settings on GET. `SameSite=lax` still sends the cookie on top-level
  navigation, so a crafted link could bind the server to an attacker's Last.fm session. Require a
  `state` nonce stored at `connect` time.
- Google Fonts loaded from a CDN (`nuxt.config.ts:110-112`) leaks every page view to Google, breaks
  offline PWA use and complicates the CSP. Self-host with `@nuxt/fonts` or `@fontsource/*`.
- Log files `/tmp/dmp-<session>.log`/`.sh` live in world-readable `/tmp` and are never removed. Move them
  under `data/logs/terminal/` and prune old ones.

## 2. Correctness bugs

### BUG-01 P1: Explore always samples the same 500 tracks
- **Where:** `server/api/tracks/explore.post.ts:66-86`.
- **Problem:** the comment says "Fetch a random sample" but the query is `findMany({ where, take: 500 })`
  with **no `orderBy`**. Postgres returns the first 500 qualifying rows in physical or index order, so
  for a given era/familiarity combination Explore only ever draws from the same 500 of 2M tracks. The JS
  shuffle afterwards only reorders that fixed set. The query also selects `metadata` (full tag JSON) for
  all 500 rows, and `excludeIds` is an unbounded client array fed straight into `notIn`.
- **Fix:** sample first (see BUG-02's `SYSTEM_ROWS` approach, or `WHERE id >= <random cuid prefix>`
  keyset with wraparound), then apply the era/plays filters. Select only the metadata keys the scorer
  reads (BPM and mood keys) with `metadata->'IntegerBpm'`-style projections in raw SQL. Cap `excludeIds`
  at 200. Also dedupe `ERA_RANGES` (route) against `ERA_CONFIGS` (`server/utils/explore.ts`).

### BUG-02 P1: every "random" endpoint is biased or drawn from a fixed subset
- **Where:** `server/api/tracks/random.get.ts:10`, `server/utils/randomBatch.ts:14`,
  `server/api/artists/random.get.ts:6`, `server/utils/subsonic/endpoints/lists.ts:122,153`.
- **Problem:**
  - `TABLESAMPLE BERNOULLI(p) … LIMIT n` samples rows in physical scan order and stops at `n`. The result
    is strongly biased toward the first heap pages (the oldest-indexed tracks). BERNOULLI also reads
    pages sequentially; the "O(1) regardless of table size" comment is wrong.
  - Subsonic `getRandomSongs` and `getAlbumList2?type=random` take the first 2000 ids with no `orderBy`,
    shuffle, and slice. Clients only ever see a fixed 2000-row subset, and `offset > 2000` returns empty.
  - The catalogue shuffle in `stores/player.ts` inherits the bias.
- **Fix:** enable `tsm_system_rows` (a contrib extension shipped with Postgres) and use
  `SELECT … FROM "LocalReleaseTrack" TABLESAMPLE SYSTEM_ROWS(${n * 20}) ORDER BY random() LIMIT ${n}`.
  That is page-random, reads O(n) pages, and is uniform enough. Put it in one `randomRows(table, n, where)`
  helper shared by the four call sites.

### BUG-03 P1: favorite state is wrong past the newest 100 releases / 50 tracks
- **Where:** `composables/useArtistCatalogue.ts:53` (`/api/favorites?type=releases&pageSize=100`),
  `components/artist/TrackList.vue:37` (`/api/favorites` with the default `pageSize` 50, fetching both
  releases and tracks).
- **Live impact:** low today (7 favorite releases across all users), but the bug grows with use.
- **Problem:** hearts render empty for older favorites. Clicking one re-favorites (an upsert no-op)
  instead of unfavoriting, so the user can't remove it from the artist page. `TrackList` refetches on
  every mount (and pulls favorite releases it doesn't need), so each expanded release fires its own
  favorites request.
- **Fix:** return `isFavorite` inside `/api/artists/[slug]/releases` and `/api/releases/[id]/tracks` using
  the existing `favoriteReleaseDates`/`favoriteTrackDates` helpers, which are already scoped to the page's
  ids. Delete both client-side fetches.

### BUG-04 P1: silent truncation on large artists
- **Where:** `composables/useArtistPage.ts:30` (`pageSize: 500`, never fetches page 2),
  `server/api/artists/[slug]/tracks.get.ts:44` (`take: 2000`, ordered by album title),
  `server/api/playlists/[slug].get.ts:24` (`take: 500`).
- **Problem:** artists whose catalogue (owned plus MB gap cards) exceeds 500 lose the tail (live: Bach
  has 5,848 MB releases and Mozart 5,790; the gap cards are only album/EP, but that is still far over
  500). Artist shuffle never reaches albums alphabetically after the 2000th track (live: Billie Holiday
  5,828 local tracks, Johnny Cash 5,768), and the query behind it is a full seq scan (see §0).
- **Correction (live):** generated playlists hold exactly 500 tracks because `./playlists` caps them
  there, so the web's `take: 500` doesn't truncate anything today. Keep it but make it a named constant
  shared with the page, and note the coupling.
- **Fix:** artist page: return the full list (with PERF-04 it becomes cheap), or page properly with a
  "load more". Artist tracks: `UNION` of two indexed lookups, then a random 500 server-side (the shuffle
  doesn't need every row).

### BUG-05 P1: `dmp_timeline` materialized view doesn't exist
- **Where:** `server/api/timeline/decades.get.ts`, `[decade].get.ts`, `refresh.post.ts`. No migration
  or script creates `dmp_timeline` (checked with grep across `web/`, `scripts/` and docs).
- **Problem:** `POST /api/timeline/refresh` always returns 500. Every uncached timeline request first
  runs a failing query (an ERROR line in the Postgres log) before the `catch` fallback. `docs/redis.md`
  documents a view that doesn't exist.
- **Fix:** either add a migration creating it (`SELECT decade, year, count(*)` from `LocalRelease`, plus
  a unique index for `CONCURRENTLY`) and refresh it at the end of `./tidy`, or delete the view path and
  keep only the `GROUP BY` fallback. `LocalRelease` is 140k rows and already cached for 5 minutes, so the
  fallback is fine. Recommended: delete it.

### BUG-06 P1: sidebar issue badge undercounts
- **Where:** `server/api/app-stats.get.ts:15-21`.
- **Problem:** it sums PENDING across 5 of the 7 issue tables and skips `IssueDuplicateRelease` and
  `IssueMismatchedReleaseId`.
- **Fix:** drive the badge from one issue-type registry (CONS-05) so a new type can't be missed again.

### BUG-07 P1: labs map shows the wrong numbers and mismatched images
- **Where:** `server/api/labs/map/countries.get.ts`.
- **Problem:** `COUNT(*)` over `unique_images` counts distinct cover images per country, yet it is
  labelled `artist_count` and rendered as the artist count. `images` and `image_urls` are separately
  `FILTER`ed arrays, so `images[i]` and `image_urls[i]` refer to different rows; the verify step pairs
  them anyway.
- **Fix:** count `DISTINCT a.id` in a separate aggregate, and aggregate `(image, imageUrl)` as one array
  of records.

### BUG-08 P1: play counter can drift from the play log
- **Where:** `server/utils/playEvents.ts` `applyPlayEventPatch` and `recordExternalPlay`.
- **Problem:** the `counted` flip (`updateMany`) and `recordPlay` (upsert on `LocalReleaseTrackPlay`) are
  two separate statements. A crash or connection drop between them leaves a counted event with no
  counter increment, and replay can't repair it because `counted` is already true.
- **Fix:** wrap both in `prisma.$transaction(async tx => …)`. Keep the cache invalidation outside the
  transaction.

### BUG-09 P2: Subsonic full-library sync is quadratic
- **Where:** `server/utils/subsonic/endpoints/search.ts` (empty query → `orderBy id, skip offset`).
- **Problem:** Symfonium-style clients page 2M songs 500 at a time. `OFFSET k` walks k index entries,
  so the total cost is ~Σk ≈ 4·10⁹ entries skipped across 4000 requests, and the later pages take seconds
  each.
- **Fix:** the protocol forces offsets, but the server can seek. Keep a small in-process checkpoint map
  `offset → id` every 10k rows (per table, invalidated by `Statistics.lastScanEndedAt`), then run
  `WHERE id > checkpointId ORDER BY id OFFSET (offset - checkpointOffset) LIMIT n`.

### BUG-10 P2: request bodies are never validated
- **Where:** 41 `readBody` calls and 0 `readValidatedBody`. `zod` is already a dependency but only used by
  `helpers/settingsValidation.ts`.
- **Problem:** `readBody` returns `undefined` for an empty body, which turns into `TypeError` 500s in
  `tracks/explore.post.ts` (`body.energy`), `playlists/index.post.ts` (`body.name`),
  `playlists/[slug]/tracks.post.ts`, `settings/index.put.ts` (`body[field]`) and
  `issues/[type]/queue.post.ts` (destructure). Type assertions such as `readBody<{…}>` give no runtime
  guarantee.
- **Fix:** a `schemas/` folder with one zod schema per mutating route and
  `readValidatedBody(event, schema.parse)`, and the same for `getValidatedQuery`. Map `ZodError` to a
  400 in a Nitro error hook.

### BUG-11 P2: config resolved from different sources in different places
- **Where:** `server/utils/promote.ts:28` and `downloadEnvironment.ts:17` read `MUSIC_DIR` from env only.
  `serveTrack.ts:23` uses `getCachedSettings().musicDir` (the DB value wins over env).
- **Problem:** if `Settings.musicDir` is set in the UI, merges land in the env root while playback serves
  from the DB root, and the environment probe checks the wrong directory. **Latent** today:
  `Settings.musicDir` is NULL in prod, so both paths resolve to the env value.
- **Fix:** one `resolveMusicDir()` inside the unified settings resolver (CONS-07).

### BUG-12 P2: settings cache serves env defaults right after boot
- **Where:** `server/utils/settingsCache.ts` `getCachedSettings()`.
- **Problem:** on a cold cache it fires a background refresh and returns `defaults()`, so the first
  requests after a restart use env values (`musicDir`, `imageStorage`). Every request after expiry
  starts its own `refreshCache()` (no in-flight dedupe).
- **Fix:** warm the cache in a Nitro plugin (`await refreshCache()` before serving) and keep a single
  in-flight promise.

### BUG-13 P2: search totals double-escape
- **Where:** `server/utils/searchRank.ts` `countArtists`/`countReleases`/`countTracks` (`like.slice(1,-1)`).
- **Problem:** the pattern is already `escapeLike`d, then Prisma's `contains` escapes it again, so the
  count fallback is wrong for queries containing `%`, `_` or `\`.
- **Fix:** pass the raw query to the count helpers. Better: drop them entirely (see PERF-01's capped
  count).

### BUG-14 P2: browse infinite scroll can skip a page or stall
- **Where:** `stores/browse.ts` `loadMore`, `components/InfiniteScroll.vue`.
- **Problem:** `page.value++` runs before the fetch, and an aborted or failed fetch leaves the page
  advanced, so the retry skips one page. An `IntersectionObserver` only fires on threshold *crossings*:
  if the sentinel is still visible after a page appends (tall or 4K screens), no new event fires and
  loading stalls until the user scrolls.
- **Fix:** increment only on success. After each append, re-check with
  `sentinel.getBoundingClientRect()` and emit again, or `observer.unobserve()` then `observe()`.

### BUG-15 P2: player stalls on an unplayable track
- **Where:** `stores/player.ts` `audio.addEventListener('error')`.
- **Problem:** an `error` event (a 404 from a file missing on disk, a decode error) only pauses. A queue
  or radio session stops dead on the first bad file. `playEvents` never finishes that event.
- **Fix:** on error, finish the event as skipped, toast "Skipped unplayable track", then call `next()`
  with a consecutive-failure breaker (stop after 3).

### BUG-16 P2: races and nondeterminism
- `playlists/index.post.ts`: a `findFirst` then `create` TOCTOU means two concurrent creates hit P2002,
  which surfaces as a 500. Catch `isUniqueConstraintError` → 409, the same pattern as
  `users/index.post.ts`.
- `playlists/[slug]/tracks.post.ts`: `MAX(position)+1` inside a READ COMMITTED transaction lets two
  concurrent adds get the same position. Use `pg_advisory_xact_lock(hashtext(playlistId))`, or order by
  `(position, createdAt)` and tolerate ties.
- `releases/[id]/tracks.get.ts`: `localReleases: { take: 1 }` has no `orderBy`, so which duplicate
  folder plays for an MB release is arbitrary. Order by `createdAt` or prefer COMPLETE.
- `userPlays.ts` `periodStart`: "today/month/year" use the container's timezone (UTC), not the user's.
  Accept `tz` from the client (`Intl.DateTimeFormat().resolvedOptions().timeZone`) and compute the
  boundaries in SQL with `AT TIME ZONE`.

### BUG-18 P1 (new): shared Redis caches are never invalidated after scans or merges
- **Where:** only `artists/[slug]/photo.post.ts`, `artists/[slug].patch.ts` and `artists/added/[mbid].post.ts`
  call `invalidateCache`. Nothing does after `./index`, `./sync`, `./tidy`, `./delete`, auto-scan, the gaps
  cycle or a download merge (the scripts can't reach Redis).
- **Problem:** after a rescan the artist header stays stale for up to 10 minutes, the artist list for 2,
  and stats for 5. PERF-04 would add a per-artist catalogue cache and make this worse, which makes this a
  prerequisite.
- **Fix:** a "library version" folded into every shared cache key. Every lock-holding script bumps
  `Statistics.updatedAt` on lock acquire, lock release and checkpoints (`scripts/common/src/lock.rs:35,90,107`,
  `checkpoint.rs`), so `libraryVersion()` = that timestamp, read with a 5s in-process TTL. Keys become
  `lib:<version>:<key>`; old keys expire by TTL, with no SCAN needed. Web-side mutations (photo, patch)

## 3. Performance at scale

### PERF-01 P0: search and substring filters seq-scan 2M rows and sort every match
- **Where:** `server/utils/searchRank.ts` (the dropdown fires artists, releases and tracks in parallel on
  every keystroke ≥2 chars); `stats/[type].get.ts` `contains` filters; `artists/index.get.ts` search;
  `genres` search.
- **Live evidence:** track search for "love" = Parallel Seq Scan with 5 workers, 2.5 GB of buffers,
  413 ms warm, 72k rows sorted to return 6. The dropdown fires three of these in parallel per keystroke
  (after the existing 300 ms debounce in `SearchInput.vue`).
- **Problem:**
  - There is no `pg_trgm` index anywhere (the extension isn't even installed). `schema.prisma:401` claims
    "Trigram GIN index for title ILIKE and expression index on LOWER(genre) added via raw migration", but
    no migration creates either.
  - `ILIKE '%q%'` on `LocalReleaseTrack.title` is a full scan of 2M rows.
  - `count(*) OVER()` forces the whole match set to be materialized and sorted before `LIMIT`. A query
    like "the" or "love" sorts hundreds of thousands of rows per keystroke.
  - `rankedReleaseIds` ORs across a LEFT JOIN (`lr.title ILIKE … OR mbr.title ILIKE …`), which no index
    can serve even after trigram indexes exist.
- **Fix:**
  1. Migration: `CREATE EXTENSION IF NOT EXISTS pg_trgm;` then GIN `gin_trgm_ops` on
     `LocalReleaseTrack(title)`, `LocalRelease(title)`, `MusicBrainzRelease(title)` and `Artist(name)`.
     Allowlist them in `scripts/test-db`'s drift check, as for `20260923000100`. Prisma wraps migrations
     in a transaction, so `CONCURRENTLY` isn't available. Build them in a maintenance window: expect
     ~1-3 min and a write lock on `LocalReleaseTrack`.
  2. Replace `count(*) OVER()` with a capped count, `SELECT count(*) FROM (SELECT 1 … LIMIT 1001) s`, and
     render "1000+".
  3. Split the release ranker into `UNION` of two indexed branches (LocalRelease title, MB title → its
     LocalReleases), then rank.
  4. Trigrams need ≥3 characters. A 2-character `'%ab%'` can't use a trigram index and would still seq
     scan. Require ≥3 characters for track and release substring search, and keep 2 for artists (46k
     rows, cheap).
  5. Client: the 300 ms debounce already exists (`SearchInput.vue`). Add abort of the in-flight request.
  6. Fix the stale schema comment.

### PERF-03 P1: `/api/artists?sort=releases|playCount` loads everything
- **Where:** `server/api/artists/index.get.ts:74-106`, `server/utils/artistReleaseStats.ts`.

- **Downloads page** (`stores/downloads.ts`): `/api/downloads/queue` runs every 2s **as long as

### PERF-12 P2: cache layer gaps

### PERF-13 P2: artist shuffle and related-artists queries

### PERF-14 P2: database connection and statement hygiene
- There is no `statement_timeout`, so a runaway stats or labs query holds a pool connection indefinitely.
  Prisma's default pool (`num_cpus*2+1`) is small next to parallel dashboard requests.
- **Live:** there is no server-side `statement_timeout`, and the web, the scripts and migrations share
  the superuser `dmp` role, so a role-level timeout would hit the Rust scans too (see SEC-09).
- **Fix (code-only, now):** a `withStatementTimeout(ms, tx => …)` helper that runs
  `SET LOCAL statement_timeout` inside `prisma.$transaction` for the known-heavy endpoints (stats,

- **Fix (later, with D3):** a role-level `statement_timeout` on a dedicated web role.

- **Live:** 326k dead tuples (17% of 1.9M), last autovacuum on 2026-09-18. The default

## 4. Robustness and operations

### ROB-01 P1: `maxBuffer` kills long script runs
- **Where:** `autoScan.ts:58`, `promote.ts:40` (`runReconciler`), `monitorLoop.ts:368` (gaps).
- **Problem:** `execFile` buffers stdout and stderr in memory and **kills the child** once output exceeds
  `maxBuffer` (64MB). An unattended `./index` + `./sync` + `./tidy` over 2M files can plausibly pass that,
  which aborts the scan mid-run while holding the DB lock (the 10-min stale-lock recovery then kicks in).
- **Fix:** a shared `runScript(name, args)` built on `spawn`, streaming to `monitorLog` or a rotating
  file, keeping only the last N lines for the error message. See CONS-08.

### ROB-02 P1: timeouts that don't cancel
- **Where:** `monitorLoop.ts` `withTimeout` (reconcile relocate at line 168, drainEnriching transform).
- **Problem:** after 5 minutes the race rejects, the row is `failAttempt`ed, `purgeDownloadedSourceFiles`
  runs, and `finalizing.delete(id)` fires. The original relocate/transcode **keeps running**: it moves
  files into a staging folder for a row already marked FAILED, racing the purge. The result is orphaned
  or partial staging folders. The timer is never cleared.
- **Fix:** thread an `AbortSignal` into `relocateDownloadedFiles`, `transcodeDirToMp3320` (pass `signal` to
  `execFile`) and the layout transform. Keep the id in `finalizing` until the underlying promise settles.
  Clear the timer.

### OPS-01 P1: runtime and container sizing
- The Dockerfile uses `node:20-bookworm(-slim)`. Node 20 reached end of life on 2026-04-30 and gets no
  security fixes. CI tests on Node 22, so prod runs an untested runtime. Move to `node:22` (or 24 LTS) in
  both.
- The Dockerfile runs `npm install -g prisma@6` unpinned, so the CLI can drift from `@prisma/client`.
  Pin the exact version from `pnpm-lock.yaml`.
- `docker-compose.yml` caps `web` at `memory: 2G`, and the Rust scripts (index, sync, tidy, mosaic)
  run **inside the same container** under tmux. A memory-hungry scan OOM-kills the web server along with
  it. Either run scripts in a sibling `dmp-scripts` container (same image, `docker exec`/job runner), or
  raise the limit and set `NODE_OPTIONS=--max-old-space-size` so Node yields first.

### OPS-02 P2: healthcheck doesn't check dependencies
- **Where:** `server/api/health.get.ts` → `{ ok: true }`.
- **Problem:** the container reports healthy while Postgres is unreachable, and `cloudflared` waits on
  `service_healthy`.
- **Fix:** `/api/health?deep=1` runs `SELECT 1` (1s timeout) and a Redis `PING` (optional). Point the
  Docker healthcheck at the deep variant and keep the shallow one for liveness.

### OPS-03 P2: SSE streams have no heartbeat
- **Where:** `terminal/run.post.ts`, `terminal/reconnect.post.ts`, `downloads/merge-stream.post.ts`,
  `labs/mosaic/generate.post.ts`.
- **Problem:** Cloudflare Tunnel closes idle HTTP streams after ~100s. A sync phase that prints nothing
  for 2 minutes drops the terminal stream.
- **Fix:** a shared SSE helper (CONS-06) that writes `: ping\n\n` every 20s, and sets
  `X-Accel-Buffering: no`.

### OPS-04 P2: outbound HTTP without timeouts
- **Where:** `slskd.ts` `slskdFetch`, `lastfm.ts`, `musicbrainz.ts`. Only `genius.ts` sets
  `AbortSignal.timeout`.
- **Problem:** a hung slskd or MusicBrainz call pins request handlers and monitor workers indefinitely.
  The loop's `running` flags then block every future cycle.
- **Fix:** one `fetchJson(url, { timeoutMs = 10_000, retries })` helper, used everywhere.

### OPS-05 P2: error visibility
- 40 silent `catch {}` / `.catch(() => {})` in UI code and 31 `console.*` calls. Users get no feedback
  when an action fails (favorite, playlist add, release info).
- The server has no structured request logging and no request ids. 5xx errors go only to stdout.
- **Fix:** a client `useApi()` wrapper over `$fetch` that toasts on non-abort errors (the toast store
  exists). Server: a Nitro `error` hook logging `method path status userId duration` and the stack for
  5xx, plus consola with JSON output in production.

### OPS-06 P2: CI gaps
- `.github/workflows/web-tests.yml` never runs `pnpm lint`.
- Both the integration DB (`test/setup/db.ts` `pushSchema`) and the e2e DB (`e2e/with-test-db.ts`
  locally, `pnpm db:push` in CI) are built with `prisma db push`, not `prisma migrate deploy`. The raw-SQL
  objects (the `Playlist` CHECK, partial unique slug, `FavoriteRelease` XOR CHECK, pattern_ops indexes,
  and the trigram indexes once PERF-01 lands) **don't exist in any web test database**. The ownership
  invariants those CHECKs enforce are never exercised, and migrations are never smoke-tested from the
  web side.
- There are no integration tests for terminal auth (SEC-01), search, artist releases, or the
  Subsonic random and sync paths.
- **Fix:** add lint; switch `pushSchema` to `prisma migrate deploy` (the scripts CI already does this);
  add those tests. Add an **EXPLAIN guard** suite:
  seed ~200k tracks in the integration DB and assert `Index Scan`/`Bitmap Index Scan` (no `Seq Scan` on
  `LocalReleaseTrack`) for the search, stats, artist-releases and random queries, so the scale
  regressions in section 3 can't come back silently.

### OPS-08 P1 (new): `./deploy` restarts on the new image before migrating
- **Where:** repo-root `deploy`: `docker compose up -d web`, then `sleep 3`, then
  `docker compose exec -T web prisma migrate deploy`.
- **Problem:** for a few seconds (longer while a migration builds an index) the new code runs against the
  old schema. With an additive column that means 500s. If the migration fails, the new code keeps running
  against the old schema indefinitely.
- **Fix:** migrate first with the new image, and only start it if the migration succeeds:
  `sudo docker compose run --rm --no-deps -T web prisma migrate deploy --schema=prisma/schema.prisma && sudo docker compose up -d web`.
  Take a `./backup` first when the ledger (Part II) has pending destructive migrations.

### OPS-09 P2 (new, live probe): no query observability on the server
- **Live:** `pg_stat_statements` is available but not installed, and `log_min_duration_statement = -1`.
  Nobody can tell which queries produce the 5.85B seq-scan tuple reads on LocalReleaseTrack or the 4.0B

# Part II: Execution plan

This plan is written for an autonomous implementer (Sonnet). Work top to bottom. Every task is **one

## II.1 Hard rules

### Database: the live library is one typo away
1. **`web/.env` → `DATABASE_URL` is the LIVE production database** (NAS 192.168.1.241, shared by the NAS
   container and local dev). Never run any of these against it:
   - `prisma db push` / `pnpm db:push`, or `prisma migrate dev|deploy|reset|resolve`
   - `pnpm db:seed`
   - any INSERT/UPDATE/DELETE/DDL through psql
   - bare `playwright test` / `pnpm test:e2e:direct`
   - `./nuke`, `./delete`, `./fix`, `./restore` pointed at it
   - `./deploy`
2. **Read-only prod inspection is allowed** and encouraged, to re-verify a premise before a DB task. Use
   exactly this form. The session is forced read-only and time-boxed:
   ```bash
   ssh nas "sudo -n docker exec -i -e PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=30s' \
     ix-postgres-postgres-1 psql -U dmp -d dmp -X -q -v ON_ERROR_STOP=1 -P pager=off" < query.sql
   ```
   Only `SELECT` and plain `EXPLAIN`. Run `EXPLAIN ANALYZE` only on a query the app already runs per
   request, never on anything the app doesn't run. Never `docker restart`/`compose` anything on the NAS,
   and never edit files there.
3. **Schema changes:**
   - Edit `web/prisma/schema.prisma` and hand-write
     `web/prisma/migrations/<YYYYMMDDHHMMSS>_<snake_name>/migration.sql`. Use timestamps after
     `20260925000000`, strictly increasing in task order.
   - Run `cd web && pnpm db:generate`.
   - Validate only on throwaway databases: `scripts/check --db` (testcontainers + `prisma migrate deploy`
     + drift check) and `pnpm test:unit` (integration project).
   - Never apply a migration to prod. **The user deploys.**
4. **Allowed migration kinds:**
   - additive tables and columns (nullable or defaulted)
   - `CREATE INDEX` / `DROP INDEX` for indexes named in this plan
   - `INSERT … ON CONFLICT DO NOTHING` into `RolePermission`
   - `ALTER TABLE … SET (storage params)`
   - `DROP COLUMN`/`DROP TABLE` **only** for the objects DEAD-03 lists as verified empty. Re-verify with
     a read-only query in the same task.

   Anything else counts as critical: stop and ask (§II.2).
5. **Index migrations:**
   - One index per migration file, written as
     `CREATE INDEX CONCURRENTLY IF NOT EXISTS …` / `DROP INDEX CONCURRENTLY IF EXISTS …`.
   - If `scripts/check --db` fails with "cannot run inside a transaction block", switch that file to the
     plain non-concurrent form and mark it **"locks writes during build"** in the deploy ledger (§II.5).
   - Any index Prisma can't declare (GIN, trigram, partial) goes into `RAW_INDEXES` in `scripts/test-db:48`,
     or the drift check fails.
6. **Every migration adds a row to the deploy ledger (§II.5)** in the same commit: its name, lock
   behaviour, expected duration, and anything the deploy needs (for example, a rebuilt scripts image).

### Git
7. Commit directly on `master` (repo convention: never branch), one commit per task, then `git push`.
   Use Conventional Commits: `type(scope): summary`, with the finding and task ids in the body
   (`Closes SEC-01 (T01).`).
8. **No `Co-Authored-By`, no "Generated with", no attribution lines of any kind.** The user's global
   rule overrides any harness default.
9. In the same commit, tick the task's box in §II.4 (`- [x]`) and fill any ledger row it created.
   Never commit `countries.html`, `venv/` or anything under `web/.env*`.
10. If a task's premise turns out already fixed or not reproducible, tick it as
    `- [x] … — n/a: <one-line reason>` inside the next real commit. Don't make empty commits.

### Quality gates (every commit)
11. Run `cd web && pnpm lint && pnpm typecheck && pnpm test:unit`. `./deploy` runs lint and typecheck
    too, so they must stay green.
12. For UI or flow changes, also run `pnpm test:e2e`. **Never** bare `playwright test`: `pnpm test:e2e`
    boots its own database.
13. For Rust changes: `cd scripts && cargo build --release && cargo clippy --all-targets -- -D warnings`,
    then `scripts/check` (`--db` if SQL changed).
14. Tests per CLAUDE.md: new pure logic goes into an importable helper with a unit test, following the
    `server/utils/audioRange.ts` pattern. Route handlers are rarely tested directly, so extract the
    decision logic (for example an auth decision) into a util and test that.
15. Follow the CLAUDE.md coding standards: arrow functions, braces on every `if`, ternaries preferred,
    no HTML comments, Tailwind only, constants in `helpers/constants.ts`, the Prisma singleton,
    `lucide-vue-next` icons. When behaviour, API or pages change, update `CLAUDE.md` and the matching
    `docs/*` in the same commit.
16. You cannot log in to the running app to look at UI changes: there is no password, and the user's rule
    is to ask instead. Rely on e2e, and list every UI-visible task in the final report for the user to
    eyeball.

## II.2 When to stop and ask the user (the only cases)
- Anything that would **write to the prod database or the NAS**, including running `./deploy`.

  data).
- An auth or permission change that could lock the admin out, if T08's ADMIN-implicit rule somehow
  can't hold.
- A test that can only be made green by weakening what it asserts.

note it in the final report, and keep going.
